# ระบบจองรถส่วนกลาง (ภาษาไทย)

เว็บแอปสำหรับตรวจสอบสถานะรถในรูปแบบปฏิทิน จองรถ บันทึกการใช้รถ และพิมพ์ใบขออนุญาตใช้รถส่วนกลาง/รถรับรอง (A4 แนวตั้ง)

**กฎการจองตามค่าเริ่มต้น:** จองแล้วยืนยันทันที ไม่ต้องรออนุมัติ และรถ 1 คันจองได้ 1 รายการต่อวัน (วันไม่ซ้ำ) ผู้ดูแลเปลี่ยนได้ที่หน้า **ตั้งค่า → กฎการจอง** ว่าจะให้ต้องอนุมัติก่อน หรือให้ตรวจเป็นรายช่วงเวลาแทน (วันเดียวกันจองได้หลายรายการถ้าเวลาไม่ทับกัน)

- ไม่ต้องติดตั้งแพ็กเกจเพิ่ม ใช้ **Node.js 22.13 ขึ้นไป** (ทดสอบกับ Node 24) ซึ่งมีฐานข้อมูล SQLite ในตัว (`node:sqlite`)
- ข้อมูลเก็บในไฟล์ `data/booking.db` อยู่ครบหลังรีเฟรชหรือรีสตาร์ต
- วันเวลาเก็บเป็น UTC และแสดงผล/รับค่าเป็นเวลาไทย **Asia/Bangkok** (UTC+7) ปี พ.ศ.

## เปิดใช้งาน

```bash
npm start            # เปิดที่ http://127.0.0.1:3000
npm install          # ครั้งแรก: ติดตั้งเครื่องมือทดสอบ (ใช้เฉพาะตอนทดสอบ)
npm test             # ทดสอบเซิร์ฟเวอร์ Node และฐานข้อมูล Supabase (ผ่าน PGlite)
npm run reset-demo   # ล้างและสร้างข้อมูลตัวอย่างใหม่ (ข้อมูลจริงไม่ถูกลบ)
```

ตัวแปรสภาพแวดล้อม:

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | `3000` | พอร์ต |
| `HOST` | `127.0.0.1` | ตั้งเป็น `0.0.0.0` เพื่อเปิดจากมือถือในวง LAN (ดูข้อควรระวังเรื่องสิทธิ์ด้านล่าง) |
| `DB_PATH` | `data/booking.db` | ตำแหน่งไฟล์ฐานข้อมูล |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / `admin1234` | บัญชีผู้ดูแลตอนสร้างฐานข้อมูลครั้งแรกเท่านั้น (หลังจากนั้นเปลี่ยนที่หน้าตั้งค่า) |

ตัวอย่างบน Windows PowerShell: `$env:PORT=8080; npm start`

## ใช้งานบนอินเทอร์เน็ตฟรี: GitHub Pages + Supabase

หน้าเว็บอยู่บน GitHub Pages ส่วนข้อมูลอยู่ใน Supabase (PostgreSQL) กฎสำคัญทั้งหมดทำงานในฐานข้อมูล ได้แก่ กันจองซ้ำ เลขที่ตามทะเบียน รหัสลับการจอง และสิทธิ์ผู้ดูแล จึงปลอมจากหน้าเว็บไม่ได้ ดูรายละเอียดใน `supabase/schema.sql`

**1. สร้างฐานข้อมูล Supabase**
1. สมัคร/เข้า supabase.com → **New project** (Region: Southeast Asia (Singapore)) ตั้งรหัสผ่านฐานข้อมูลแล้วเก็บไว้
2. เมนู **SQL Editor** → New query → วางเนื้อหาไฟล์ `supabase/schema.sql` ทั้งไฟล์ → **Run** (รันซ้ำได้ ไม่ลบข้อมูล)
3. (ถ้าต้องการย้ายข้อมูลจากเครื่องนี้) รัน `npm run export-supabase` จะได้ไฟล์ `data/supabase-import.sql` → วางใน SQL Editor แล้ว Run ใช้กับโปรเจกต์ใหม่ที่ยังไม่มีข้อมูลเท่านั้น และ**อย่า push ไฟล์นี้ขึ้น GitHub** เพราะมีข้อมูลจริง (อยู่ใน .gitignore แล้ว)

**2. สร้างบัญชีผู้ดูแล (บัญชีเดียว)**
1. **Authentication → Sign In / Providers**: ปิด **Allow new users to sign up** (สำคัญ ไม่งั้นใครก็สมัครได้ แม้จะยังไม่ได้สิทธิ์ผู้ดูแล)
2. **Authentication → Users → Add user → Create new user**: ใส่อีเมลและรหัสผ่านผู้ดูแล ติ๊ก **Auto Confirm User**
3. SQL Editor → รันคำสั่งนี้ (เปลี่ยนอีเมลเป็นของคุณ):
   ```sql
   insert into admin_users(user_id, display_name)
   select id, 'ผู้ดูแลระบบ' from auth.users where email = 'อีเมลผู้ดูแล@example.com';
   ```
   ล็อกอินในหน้าเว็บด้วยอีเมลนี้ เปลี่ยนรหัสผ่านได้ที่หน้าตั้งค่า หรือที่ Supabase → Authentication → Users

**3. เชื่อม GitHub Pages**
1. Supabase → **Project Settings → API**: คัดลอก **Project URL** และ **anon public key** (anon key เป็นค่าสาธารณะ ใส่ในหน้าเว็บได้ ความปลอดภัยอยู่ที่ Row Level Security)
2. GitHub repository → **Settings → Secrets and variables → Actions → แท็บ Variables → New repository variable**: เพิ่ม `SUPABASE_URL` และ `SUPABASE_ANON_KEY`
3. GitHub repository → **Settings → Pages → Source: GitHub Actions**
4. push ขึ้น `main` (หรือเปิดแท็บ Actions → GitHub Pages → Run workflow) แล้วรอ 1–2 นาที หน้าเว็บจะอยู่ที่ `https://<ชื่อบัญชี>.github.io/<ชื่อ-repo>/`

ข้อควรรู้
- GitHub Pages ฟรีสำหรับ repository แบบ Public (แบบ Private ต้องใช้ GitHub Pro ขึ้นไป) โค้ดเปิดเผยได้ ข้อมูลจริงอยู่ใน Supabase ไม่ได้อยู่ใน repository
- Supabase แผนฟรีจะพักโปรเจกต์ที่ไม่มีการใช้งานนาน 7 วัน (เข้า Dashboard แล้วกด Restore ได้) ถ้าใช้งานทุกวันจะไม่ถูกพัก
- รายชื่อบุคลากรที่ผู้ไม่ได้ล็อกอินเห็นจะไม่มีเบอร์โทร (อ่านผ่าน `people_public`) ส่วนตารางการจองอ่านได้เฉพาะผ่านฟังก์ชันที่ตรวจรหัสลับ
- ในโหมด Supabase ปุ่ม "รีเซ็ตข้อมูลตัวอย่าง" จะไม่แสดง (ฐานข้อมูลเริ่มต้นแบบว่าง มีเฉพาะประเภทรถตามแบบฟอร์ม)
- ยังรันแบบเดิมในเครื่องได้ด้วย `npm start` (ไฟล์ `public/config.js` ค่าว่าง = ใช้เซิร์ฟเวอร์ Node)

## Deploy แบบมีเซิร์ฟเวอร์ (GitHub + บริการโฮสต์)

**GitHub Pages ใช้ไม่ได้** เพราะ Pages เปิดได้แค่ไฟล์ static ส่วนระบบนี้ต้องมีเซิร์ฟเวอร์ Node.js และไฟล์ฐานข้อมูลที่บันทึกถาวร จึงเก็บโค้ดไว้บน GitHub แล้วให้บริการโฮสต์ดึงไปรัน

1. สร้าง repository บน github.com (แนะนำแบบ **Private**) แล้ว push โค้ดขึ้นไป
2. ทุกครั้งที่ push, GitHub Actions (`.github/workflows/test.yml`) จะรันชุดทดสอบและ build Docker image ให้อัตโนมัติ
3. เลือกที่รัน:
   - **Render** (ง่ายที่สุด): New → Blueprint → เลือก repository ระบบจะอ่าน `render.yaml` แล้วสร้างเว็บพร้อม Persistent Disk ที่ `/data` และ deploy ใหม่ทุกครั้งที่ push ให้ใส่ค่า `ADMIN_PASSWORD` ในหน้า Render ก่อน deploy ครั้งแรก (Persistent Disk ต้องใช้แผนเสียเงิน Starter ขึ้นไป)
   - **Railway / Fly.io / เซิร์ฟเวอร์ที่มี Docker**: ใช้ `Dockerfile` แล้ว **ต้องต่อ volume ถาวรไว้ที่ `/data`** ไม่งั้นข้อมูลจะหายทุกครั้งที่ deploy ใหม่
   - **เครื่องเซิร์ฟเวอร์ในสำนักงาน**: `git clone` แล้วรัน `HOST=0.0.0.0 npm start` (ใช้ pm2 หรือ Windows Task Scheduler ให้เปิดเองตอนเปิดเครื่องได้)

ค่าที่ควรตั้งบนเซิร์ฟเวอร์จริง:

| ตัวแปร | ค่า | เหตุผล |
|---|---|---|
| `ADMIN_PASSWORD` | รหัสผ่านที่คาดเดายาก | ใช้ตอนสร้างฐานข้อมูลครั้งแรก (ไม่งั้นจะเป็น `admin1234`) |
| `DB_PATH` | `/data/booking.db` | วางฐานข้อมูลไว้บน disk ถาวร |
| `TRUST_PROXY` | `1` | อยู่หลัง proxy ของโฮสต์: ใช้ IP จริงในการจำกัดรหัสผ่านผิด และตั้ง cookie แบบ Secure |
| `SEED_DEMO` | `0` | ไม่ใส่ข้อมูลตัวอย่าง (มีเฉพาะประเภทรถตามแบบฟอร์ม) |
| `HOST` / `PORT` | `0.0.0.0` / ตามที่โฮสต์กำหนด | Dockerfile ตั้งไว้ให้แล้ว |

> ไฟล์ฐานข้อมูล (`data/*.db`) อยู่ใน `.gitignore` จะไม่ถูก push ขึ้น GitHub ถ้าต้องการย้ายข้อมูลจากเครื่องนี้ขึ้นเซิร์ฟเวอร์ ให้คัดลอกไฟล์ `booking.db` ไปวางที่ `DB_PATH` ตอนเซิร์ฟเวอร์ปิดอยู่

| หน้า | ผู้ใช้ทั่วไป | ผู้ดูแล |
|---|---|---|
| **สถานะรถ (ปฏิทินรายเดือน):** แต่ละวันแสดงจำนวนรถว่าง/รถที่ใช้งานได้ และรถที่ถูกจองหรือซ่อม กรองตามประเภทรถหรือดูรายคัน กดที่วันเพื่อดูรถทุกคันแล้วกด "จองวันนี้" | ✓ | ✓ |
| รายการรถ | ดู | เพิ่ม แก้ไข ปิด/เปิดใช้งาน บันทึกซ่อมบำรุง |
| ตารางคิวรายสัปดาห์ (แยกตามรถ / รายการ) | เห็นคำขอผู้อื่นแค่ช่วงเวลาและหน่วยงาน | เห็นทั้งหมด |
| แบบฟอร์มจองรถ: แสดงว่ารถคันไหนว่าง พร้อมเหตุผลที่ไม่ว่าง | ✓ | ✓ |
| การจอง: สถานะ จองแล้ว / ยกเลิก / เสร็จสิ้น (ถ้าเปิดโหมดอนุมัติจะมี รออนุมัติ / อนุมัติ / ไม่อนุมัติ) | ของตนเอง ยกเลิกได้ | ทั้งหมด เปลี่ยนรถ/พนักงานขับรถ ปิดงาน และอนุมัติ/ไม่อนุมัติ (ต้องระบุเหตุผล) ในโหมดอนุมัติ |
| บันทึกการใช้รถ: เวลา เลขไมล์ขาออก-ขากลับ ระยะทางรวม ผู้ขับ | ดูในหน้าคำขอ | บันทึก/แก้ไข |
| ตั้งค่า: ข้อความบนแบบพิมพ์ ประเภทรถ ข้อมูลตัวอย่าง | – | ✓ |

### กฎสำคัญ
- **วันไม่ซ้ำ (ค่าเริ่มต้น):** รถที่มีการจองในวันใดแล้ว จองซ้ำในวันนั้นไม่ได้แม้จะต่างเวลา การจองข้ามหลายวันจะกันทุกวันในช่วงนั้น (กลับเที่ยงคืนพอดีไม่นับเป็นวันถัดไป) วันตัดตามเวลาไทย
- **จองแล้วยืนยันทันที (ค่าเริ่มต้น):** ต้องเลือกรถที่ว่างตอนจอง สถานะจะเป็น "จองแล้ว" ทันที และใช้พนักงานขับรถประจำรถเป็นค่าเริ่มต้น
- ทั้งสองโหมดตรวจรถซ่อมบำรุง รถปิดใช้งาน และรถที่ออกไปแล้วแต่ยังไม่บันทึกขากลับด้วย การตรวจทำที่เซิร์ฟเวอร์ภายใน transaction (หน้าเว็บที่เปิดค้างไว้จึงจองชนกันไม่ได้) ในโหมดรายช่วงเวลา เวลาที่ต่อกันพอดี เช่น 09–12 กับ 12–14 จองได้
- ผู้ใช้ทั่วไปจองย้อนหลังไม่ได้ จำนวนผู้เดินทางต้องไม่เกินที่นั่ง และเวลากลับต้องอยู่หลังเวลาออก
- เมื่อบันทึกเวลาและเลขไมล์ขากลับครบ คำขอจะเปลี่ยนเป็น "เสร็จสิ้น" และอัปเดตเลขไมล์รถให้อัตโนมัติ
- การดำเนินการทุกครั้งเก็บประวัติไว้ในตาราง `booking_events` (แสดงในหน้าคำขอ)

## เอกสารสำหรับพิมพ์

ในหน้ารายละเอียดการจอง กด **"ดูตัวอย่าง / พิมพ์เอกสาร"** (หรือเปิด `print.html?id=<เลขการจอง>`)

หน้าพิมพ์จัดตามแบบฟอร์มจริง **"ใบขออนุญาตใช้รถส่วนกลาง/รถรับรอง" (แบบ ๔)** ของ สนง.กกต.จว.เชียงใหม่ ทั้งลำดับบรรทัด ข้อความ ช่องทำเครื่องหมาย เส้นประ และช่องลงนาม 4 จุด (ผู้ขออนุญาต / เจ้าหน้าที่ผู้รับผิดชอบ / ผู้มีอำนาจ / พนักงานขับรถยนต์)

- กระดาษ A4 แนวตั้ง 1 หน้า ช่องลงนามไม่ถูกแยกข้ามหน้า ถ้าข้อความยาวมาก ตัวอักษรจะย่อลงเองให้พอดี (ไม่ต่ำกว่า 11pt)
- **เติมให้อัตโนมัติจากการจอง:** วันที่ยื่น ชื่อ ตำแหน่ง ฝ่าย/กลุ่มงาน ประเภทรถ (ทำเครื่องหมาย) สถานที่ไปปฏิบัติงาน วัตถุประสงค์ (ต่อท้ายด้วยรายชื่อผู้ร่วมเดินทางถ้ามี) จำนวนผู้ร่วมเดินทาง (ไม่นับผู้ขอ) วันเวลาไป-กลับ และชื่อกับวันที่ใต้ลายเซ็นผู้ขอ
- **เว้นว่างไว้เขียนด้วยมือ:** ส่วนเจ้าหน้าที่ผู้รับผิดชอบ คำสั่งผู้มีอำนาจ และบันทึกการใช้รถ ถ้าต้องการพิมพ์ข้อมูลที่บันทึกในระบบ (ทะเบียนรถ ผู้ขับขี่ เวลาและเลขไมล์ ระยะทาง) ให้ติ๊ก "เติมผลพิจารณา/บันทึกการใช้รถจากระบบ" ช่อง "อนุญาต" จะถูกติ๊กเฉพาะเมื่อผู้ดูแลอนุมัติในระบบจริง (โหมดต้องอนุมัติ)
- ติ๊ก "แก้ไขข้อความก่อนพิมพ์" แล้วคลิกแก้ข้อความบนเอกสารได้เฉพาะครั้งนั้น ไม่บันทึกลงระบบ
- แก้ถาวรได้ที่หน้า **ตั้งค่า** ได้แก่ หัวข้อ รหัสแบบฟอร์ม (แบบ ๔) "เรียน" "สังกัด" สถานที่ "กลับถึง ... วันที่" และตำแหน่งใต้ลายเซ็น
- ช่องประเภทรถมาจาก **ตั้งค่า → ประเภทรถ** ตามลำดับที่ตั้งไว้ ค่าเริ่มต้นคือ รถเก๋ง รถกระบะ รถตู้ รถจักรยานยนต์ ตามแบบฟอร์ม ประเภทที่ปิดใช้งานจะไม่แสดงบนเอกสาร
- เมนูและปุ่มของแอปถูกซ่อนเมื่อพิมพ์ แนะนำให้ปิด "ส่วนหัวและส่วนท้าย" ในหน้าต่างพิมพ์ของเบราว์เซอร์ และใช้ขนาด 100%

### ปรับรูปแบบหน้าพิมพ์ (ตั้งค่า → รูปแบบหน้าพิมพ์)

ผู้ดูแลปรับได้โดยเห็นตัวอย่าง A4 สดทางขวา (เลือกแสดงจากข้อมูลสมมติหรือการจองจริง) แล้วกด **บันทึกรูปแบบ** ปุ่ม **คืนค่าเริ่มต้น** ใช้ย้อนกลับได้
- ขนาดตัวอักษร ระยะห่างบรรทัด ย่ออัตโนมัติให้พอดี 1 หน้า (กำหนดขนาดต่ำสุดได้) — ระบบแจ้งทันทีว่าเนื้อหาพอดี 1 หน้าหรือเกิน
- ระยะขอบกระดาษ บน/ล่าง/ซ้าย/ขวา, ย่อหน้า, ความกว้างคอลัมน์ซ้าย, จำนวนบรรทัด "เพื่อ", ระยะเว้นก่อนช่องลงนาม
- เปิด/ปิดส่วนเจ้าหน้าที่/คำสั่ง ส่วนบันทึกการใช้รถ รายชื่อผู้ร่วมเดินทาง ชื่อผู้ลงนาม และเลขอ้างอิง
- ผู้ลงนามเริ่มต้น (เจ้าหน้าที่ผู้รับผิดชอบ / ผู้มีอำนาจ) และข้อความทุกบรรทัดบนแบบฟอร์ม

## รายชื่อบุคลากรและรายการที่ใช้บ่อย (ตั้งค่า)

- **บุคลากร:** ผู้ดูแลเพิ่มชื่อ ตำแหน่ง ฝ่าย เบอร์โทร และหน้าที่ (เลือกได้หลายอย่าง): ผู้ขอใช้รถ / พนักงานขับรถยนต์ / เจ้าหน้าที่ผู้รับผิดชอบ / ผู้มีอำนาจ ปิดใช้งานเพื่อซ่อนจากตัวเลือกได้โดยไม่ต้องลบ
  - แบบฟอร์มจอง: ดรอปดาวน์ "เลือกจากรายชื่อบุคลากร" เติมชื่อ ตำแหน่ง ฝ่าย และเบอร์โทรให้ (ยังพิมพ์เองได้)
  - **นำเข้าจาก Excel:** ปุ่ม "นำเข้าจาก Excel" รับไฟล์ .xlsx หรือ .csv ที่มีคอลัมน์ ชื่อ-นามสกุล (จำเป็น) และ ตำแหน่ง (มี ฝ่าย/กลุ่มงาน เบอร์โทร ได้) ระบบหาแถวหัวตารางเอง แสดงตัวอย่างว่าแถวไหนเพิ่มใหม่/อัปเดต/ข้าม ก่อนกดนำเข้า ชื่อที่มีอยู่แล้วจะอัปเดตตำแหน่งและเพิ่มหน้าที่ที่เลือก ไฟล์ .xls แบบเก่าต้องบันทึกเป็น .xlsx ก่อน
  - ช่องพนักงานขับรถ (ข้อมูลรถ การกำหนดรถ บันทึกการใช้รถ): เลือกจากรายชื่อหรือพิมพ์ชื่อ ในข้อมูลรถจะเติมเบอร์โทรให้
  - หน้าพิมพ์: ดรอปดาวน์ผู้รับผิดชอบ/ผู้มีอำนาจที่แถบเครื่องมือ ชื่อจะพิมพ์ในวงเล็บใต้ลายเซ็น (เครื่องจะจำตัวเลือกล่าสุด ไม่งั้นใช้ค่าเริ่มต้นจากการตั้งค่า)
- **รายการที่ใช้บ่อย:** สถานที่และวัตถุประสงค์ แสดงเป็นดรอปดาวน์เหนือช่องนั้นในแบบฟอร์มจอง
- ชื่อถูกคัดลอกลงในการจอง ลบหรือแก้รายชื่อภายหลังจึงไม่กระทบการจองเดิม

## ข้อมูลตัวอย่าง

ครั้งแรกที่เปิด ระบบจะสร้างผู้ใช้ 3 คน รถ 6 คัน การจองหลายสถานะ และรายการซ่อมบำรุง โดยกำหนดวันที่อิงจากวันปัจจุบัน
- ข้อมูลตัวอย่างมีป้าย **"ตัวอย่าง"** และเลขคำขอขึ้นต้นด้วย `DEMO-` (คำขอจริงใช้ `RQ-<ปี พ.ศ.>-<ลำดับ>`)
- ผู้ดูแลลบหรือรีเซ็ตได้ที่หน้าตั้งค่า หรือใช้ `npm run reset-demo` / `node scripts/reset-demo.js --clear`

## การเข้าสู่ระบบและสิทธิ์

- **เจ้าหน้าที่ทั่วไปไม่ต้องเข้าสู่ระบบ:** ดูสถานะรถ ปฏิทิน และรายการรถได้ จองได้ (เลือกชื่อจากรายชื่อบุคลากร) และดู ยกเลิก หรือพิมพ์ได้เฉพาะการจองที่ทำจากเครื่องนั้น
  - การจองแต่ละรายการมีรหัสลับ (owner token) ที่เบราว์เซอร์เก็บไว้ใน localStorage แล้วส่งมากับ header `X-Booking-Tokens` ถ้าจองจากเครื่องอื่นหรือล้างข้อมูลเบราว์เซอร์ จะไม่เห็นรายการเดิม ต้องให้ผู้ดูแลจัดการแทน
  - ในปฏิทิน การจองของคนอื่นแสดงแค่ช่วงเวลาและหน่วยงาน
- **ผู้ดูแลมีบัญชีเดียว:** กด "เข้าสู่ระบบผู้ดูแล" มุมขวาบน ค่าเริ่มต้นคือ `admin` / `admin1234` ระบบจะขึ้นแถบเตือนสีแดงจนกว่าจะเปลี่ยนรหัสผ่านที่ **ตั้งค่า → ทั่วไป → บัญชีผู้ดูแล** (เปลี่ยนชื่อผู้ใช้ ชื่อที่แสดง และรหัสผ่านอย่างน้อย 8 ตัวอักษร ต้องใส่รหัสผ่านปัจจุบันทุกครั้ง)
  - รหัสผ่านเก็บแบบแฮช (scrypt + salt) ในตาราง `admin_account` แยกจากการตั้งค่าอื่น
  - session cookie แบบ HttpOnly หมดอายุเมื่อไม่ได้ใช้งาน 12 ชั่วโมง รีสตาร์ตเซิร์ฟเวอร์แล้วต้องเข้าสู่ระบบใหม่
  - ใส่รหัสผ่านผิดได้ 8 ครั้งต่อ 10 นาทีต่อเครื่อง
- **ลืมรหัสผ่านผู้ดูแล:** ปิดโปรแกรม ลบแถวในตาราง `admin_account` (เช่น `DELETE FROM admin_account;` ด้วย sqlite3) แล้วเปิดใหม่ ระบบจะสร้างบัญชีเริ่มต้นใหม่ (`ADMIN_PASSWORD` ถ้าตั้งไว้ หรือ `admin1234`)
- ถ้าจะเปิดให้เครื่องอื่นในเครือข่ายใช้ (`HOST=0.0.0.0`) ควรเปลี่ยนรหัสผ่านก่อน และถ้าใช้ผ่านอินเทอร์เน็ตควรให้บริการผ่าน HTTPS

## โครงสร้างโปรเจกต์

```
server.js            HTTP server, เส้นทาง API, ไฟล์ static
lib/db.js            สคีมาฐานข้อมูล ค่าตั้งต้นแบบพิมพ์ และข้อมูลตัวอย่าง
lib/service.js       ตรรกะทั้งหมด: สถานะรถ ตรวจเวลาทับซ้อน การอนุมัติ บันทึกการใช้รถ สิทธิ์
lib/auth.js          เข้าสู่ระบบผู้ดูแล (session/รหัสผ่าน) และรหัสลับการจองของผู้ไม่ได้ล็อกอิน
lib/time.js          จัดการเวลา Asia/Bangkok
public/index.html    หน้าแอป (SPA) + public/js/app.js + public/styles.css
public/print.html    หน้าพิมพ์ A4 + public/js/print.js + public/print.css
public/config.js     ตั้งค่า Supabase (ว่าง = ใช้เซิร์ฟเวอร์ Node)
public/js/supabase-api.js   ตัวเชื่อม Supabase (แปลง api('/api/...') เป็น REST/RPC)
public/js/printLayout.mjs   รูปแบบหน้าพิมพ์ (ใช้ร่วมกันทั้ง Node และหน้าเว็บ)
public/js/peopleImport.mjs  อ่าน Excel/CSV สำหรับนำเข้ารายชื่อ (ใช้ร่วมกัน)
supabase/schema.sql  ตาราง สิทธิ์ (RLS) และฟังก์ชันกฎการจองสำหรับ Supabase
scripts/export-supabase.js  ส่งออกข้อมูลในเครื่องเป็น SQL สำหรับ Supabase
scripts/reset-demo.js
test/api.test.js     ทดสอบเซิร์ฟเวอร์ Node (node:test)
test/supabase.test.js  ทดสอบ supabase/schema.sql ด้วย PGlite
```

ตารางหลัก: `users`, `vehicle_types`, `vehicles`, `maintenance`, `bookings`, `trip_logs`, `booking_events`, `people`, `presets`, `settings` (รูปแบบหน้าพิมพ์เก็บเป็น JSON ใน `settings.print_layout` ค่าเริ่มต้นและช่วงค่าที่อนุญาตอยู่ใน `lib/printLayout.js`)

สำรองข้อมูล: คัดลอกไฟล์ `data/booking.db` ตอนปิดโปรแกรม (หรือใช้คำสั่ง `.backup` ของ sqlite3)

## ข้อจำกัดที่ยังเหลือ

- ยังไม่มีการแจ้งเตือนทางอีเมล/LINE เมื่อคำขอได้รับอนุมัติหรือถูกปฏิเสธ
- ผู้จองแก้ไขการจองที่ส่งแล้วไม่ได้ ต้องยกเลิกแล้วจองใหม่ (ผู้ดูแลเปลี่ยนรถ/พนักงานขับรถได้)
- การเปลี่ยนกฎการจองมีผลกับการจองใหม่เท่านั้น การจองเดิมที่ซ้อนกันอยู่แล้ว (เช่น เปลี่ยนจากรายช่วงเวลาเป็นรายวัน) ระบบจะไม่ยกเลิกให้อัตโนมัติ
- ยังไม่ตรวจว่าพนักงานขับรถคนเดียวกันถูกจัดให้ขับซ้อนเวลากันหรือไม่ (ตรวจเฉพาะรถ)
- แบบอักษรโหลดจาก Google Fonts (Sarabun / IBM Plex Sans Thai) ถ้าไม่มีอินเทอร์เน็ตจะใช้แบบอักษรไทยของเครื่องแทน ถ้าต้องการให้หน้าพิมพ์คงที่แบบออฟไลน์ ให้วางไฟล์ฟอนต์ไว้ใน `public/` แล้วแก้ `print.css`
- ช่องเลือกวันเวลา (`datetime-local`) แสดงรูปแบบตามภาษาของเบราว์เซอร์ ระบบจึงแสดงสรุปวันเวลาแบบไทยไว้ใต้ช่องให้ตรวจทาน
- รองรับผู้ใช้พร้อมกันระดับหน่วยงาน (SQLite ไฟล์เดียว) ถ้าใช้งานหนักหลายสาขาควรย้ายไป PostgreSQL โดยแก้ `lib/db.js` และคำสั่ง SQL ใน `lib/service.js`
